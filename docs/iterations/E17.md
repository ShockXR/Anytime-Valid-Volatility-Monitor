## Iteration 1. The guarantee: the suggested bound is false, a certified average is proved

**OBJECTIVE.** Prove a false alarm bound for a weighted average of e-detectors run on 1-, 5- and 15-minute block returns. The task suggested `P(false alarm within m) ≤ Σ_k w_k (m / k) / A`, from the fact that an average of e-values is an e-value (Vovk and Wang 2021).

**PROBLEM IDENTIFIED.** The proof of the one-minute bound (`docs/math.md`, Lemma 1 and Theorems A and B) needs each statistic to be a fair bet on the one-minute clock: its expected next value, given everything seen so far, is at most its current value plus the step's increment. A k-minute detector changes only at block ends. One minute before a block ends, most of the block return is already known, so the expected value of the next bet is no longer 1. Proposition 2 makes this concrete with k = 2 and Gaussian returns: a stopping rule that waits for the end of a block only when its first return is large gives an expected stopped value 0.484 λ above what the proof needs. Counting blocks started instead of completed does not rescue it (part 3). So the suggested bound cannot be proved for the plain average checked every minute. Averaging e-values is valid at a fixed time, or on a common clock; the problem here is that the detectors live on different clocks (the setting of Choe and Ramdas, arXiv:2402.09698).

**HYPOTHESIS.** A coarse detector's wealth at its next block end cannot fall below `ℓ (M + 1)`, where M is its current value and ℓ the smallest possible bet factor. If the monitor credits each coarse detector between block ends only with `min(M, ℓ (M + 1))`, the credited value stays below a one-minute supermartingale (the expected wealth at the next block end), and Ville's inequality applies to the weighted sum.

**CHANGES IMPLEMENTED.** `docs/theory_multifreq.md`: the null each frequency needs (conditional on all one-minute information at the block start); when the one-minute null implies it (i.i.d. returns, a scale fixed within blocks, raw squares under martingale differences) and a counterexample when it does not; price noise and gap blocks; Proposition 2; Lemma 2 and Theorem 1 for the certified average (bound `Σ_k w_k ⌈m / k⌉ / A`, mean time to the first false alarm at least `(A - κ) / ρ`); Proposition 3 (the worst-case handicap is at least the number of frequencies, with equality for weights proportional to k); Theorem 3 (weaker bounds for the weighted maximum and for the plain average); Corollary 4 (recalibration after every alarm). References checked through web-search listings, because arxiv.org and the authors' sites were not reachable.

**EXPERIMENTS PERFORMED.** Simulation checks in `tests/test_multifreq.py`: Proposition 2, part 2, by Monte Carlo; first-alarm rates on i.i.d. streams (m = 300, A = 300, 4,000 paths) against the three bounds; alarm counts with restarts on a 120,000-minute stream against Corollary 4; the block correlations under price noise.

**RESULTS.** All checks pass. A first version of the bound test used A = 100 with m = 300, where every bound is above 1 and the test says nothing; it was changed to A = 300.

**IMPROVEMENTS.** A guarantee that is checked every minute and is better than the one-minute monitor's `m / A`. The gain is spent by lowering A until the bound is again 5% per day.

**REMAINING ISSUES.** The theorems need the true baselines. With a plug-in baseline there is no proof (as for the one-minute monitor). A confidence-sequence baseline for every frequency is sketched in section 8 of the note, not implemented.

**NEXT ITERATION.** Implement the monitor and check it against the existing one-minute monitor.

## Iteration 2. Code: one streaming class, one vectorised path, both checked against existing code

**OBJECTIVE.** A `MultiFrequencyMonitor` that takes one-minute returns, builds non-overlapping blocks, calibrates every frequency on the same window, and alarms on the certified average; and a vectorised version fast enough for 10,000-day simulations.

**PROBLEM IDENTIFIED.** Three conventions had to match the one-minute `VolatilityMonitor` exactly for the comparison to be fair: what happens to a missing return (the one-minute monitor skips it without the +1 of the recursion), how a degenerate calibration window is handled (extension, fallback to the median of nonzero values, restart), and the floor on the scale.

**HYPOTHESIS.** If the frequency-1 path reuses the same calibration logic and skips missing blocks in the same way, the multi-frequency monitor with k = 1 alone reproduces `VolatilityMonitor` event for event.

**CHANGES IMPLEMENTED.** `src/avmonitor/multifreq.py`: weights (`equal`, `balanced`, `sqrt` or explicit), `proved_bound`, `level_for_budget`, `handicap`, block construction (plain or gap), plug-in calibration on all block phases of the window, vectorised detector paths with certified values, and the streaming class with events that record the share of each frequency in the statistic. A missing one-minute return skips the whole block. A cap of 10¹² on the wealth in the vectorised path prevents overflow.

**EXPERIMENTS PERFORMED.** 17 unit tests, among them: k = 1 alone equals `VolatilityMonitor` (3 seeds, bands 0 and 0.25, with missing values and runs of zero returns); each frequency's detector equals the existing `betting_edetector` on block returns; the streaming statistic equals the weighted sum of separately computed detectors at every minute; the certified and plain averages agree at minutes that end every block; the vectorised first alarms equal the streaming ones in three combine and check modes.

**RESULTS.** All pass. Two test failures during development were in the tests: the comparison with `betting_edetector` needed the cap removed (it has none), and `betting_edetector` adds +1 at a missing step while the monitor skips it, so that comparison is made only on complete data.

**IMPROVEMENTS.** The vectorised code used in every synthetic cell is tested against the streaming class, and the streaming class against the existing monitor.

**REMAINING ISSUES.** The streaming class is about twice as slow as `VolatilityMonitor` (1.7 s against 0.9 s for 100,000 minutes on this machine); fast enough for the real data.

**NEXT ITERATION.** Synthetic experiments.

## Iteration 3. Synthetic design, and a noise level added after seeing results

**OBJECTIVE.** Measure false alarms and detection for each frequency alone and for several combinations, at the same proved budget of 5% per day, under i.i.d. laws and under price noise.

**PROBLEM IDENTIFIED.** A fair comparison needs (a) every monitor at the same proved budget, (b) a change that does not fall on a block boundary, and (c) changes that favour different frequencies; otherwise the experiment only measures the handicap. In the first run, price noise was simulated at γ = 0.5 and 1 (false alarms) and γ = 1 (changes). At γ = 1 the one-minute detector, although invalid (6.88% per day), was still the fastest single frequency for every change except the trend, so the design had no noisy case in which the coarse frequencies win.

**HYPOTHESIS.** With stronger noise (γ = 2, a noise standard deviation twice the one-minute efficient move) the one-minute returns lose most of their information, the coarse detectors become the best, and the question "does the combination help under noise?" gets a real test.

**CHANGES IMPLEMENTED.** `experiments/e17_multifrequency.py` with parts `baselines` (true truncation levels and baselines from 2 million blocks per law, frequency and block type), `levels`, `null` (10,000 days per cell, true and plug-in baselines), `change` (2,000 paths per cell, change at minute 247: six persistent changes, four bursts and a trend). Monitors, weights and levels were fixed before the first run. After the first run, γ = 2 was added to both the null and the change parts. The law is appended at the end of the list and seeds depend on the law's position, so every earlier cell was reproduced exactly when everything was rerun.

**EXPERIMENTS PERFORMED.** All synthetic parts, on 2 processes with `nice -n 10`. The null and change parts took about 1 minute each.

**RESULTS.** (Report Q17b to Q17e.) Every proved bound holds (0.32% to 2.62% per day under the i.i.d. laws). The plain every-minute average behaves like the certified one (within 0.07 points). Under i.i.d. laws the averages never beat the best single frequency but stay close: equal weights 0% to 5% slower, balanced 11% to 18%, sqrt 4% to 10% on persistent changes. On the trend the one-minute detector catches 3.8% of paths and the averages 95.5% to 97.3% (Gaussian). At γ = 2 the one-minute detector is no longer the best; the proved 5 and 15 gap average beats both proved singles for increases (×1.25: 28.1% against 21.4% and 25.3%) and loses for decreases (×0.5: 47.2% against 56.5%).

**IMPROVEMENTS.** The design now has cells where each frequency is the right one: one minute for bursts and i.i.d. shifts, 5 minutes for the trend, coarse frequencies under strong noise.

**REMAINING ISSUES.** The γ = 2 choice was made after seeing the γ = 1 results; the report says so. The trend is one kind of dependence. The synthetic laws have no volatility clustering.

**NEXT ITERATION.** Real data, with the settings written down before the first run.

## Iteration 4. Real data with settings frozen in advance

**OBJECTIVE.** Run the monitors on the five Binance coins of E6 (1 July to 31 December 2025) with E6's validation, without any tuning on the real data.

**PROBLEM IDENTIFIED.** With seven monitors and several validation measures, choosing settings after seeing real results would make any difference between monitors hard to trust.

**HYPOTHESIS.** If one-minute returns on these coins carry little noise (E13 measured lag-one autocorrelations of -0.016 to +0.027 for BTC, ETH, XRP and SOL and +0.132 for DOGE), the averages should behave like the one-minute monitor, as in the i.i.d. synthetic cells.

**CHANGES IMPLEMENTED.** The real settings (data, deseasonalisation as in E6, monitors, plain blocks, band 0.25, calibration and recalibration, validation, the descriptive measures and the comparisons to report) were written into the script's docstring and committed (34c6155) before the real part was run for the first time.

**EXPERIMENTS PERFORMED.** `python experiments/e17_multifrequency.py real` on 2 processes; one run.

**RESULTS.** (Report Q17f.) The one-minute monitor reproduces E6 exactly (127, 122, 129, 123 and 126 alarms; 369 up and 258 down). The averages alarm 0.65 to 0.68 times per day with validation shares equal to the one-minute monitor's or up to 4 points lower. At their alarms the one-minute detector makes up 98.4% to 99.7% of the statistic. The 5-minute and 15-minute detectors alone alarm less often (0.43 and 0.26 per day) and are confirmed more often (up 90% and 95%), which is not a comparison at equal alarm rates. No calibration window needed an extension or a fallback.

**IMPROVEMENTS.** A clean real-data answer: on these coins the combination is the one-minute monitor with a small delay.

**REMAINING ISSUES.** The coarse nulls may fail on real data in ways the one-minute null does not (volatility clustering, dependence inside blocks). The plug-in baseline has no proof.

**NEXT ITERATION.** Figure and report.

## Iteration 5. Figure

**OBJECTIVE.** One figure of median delays for persistent changes.

**PROBLEM IDENTIFIED.** The figure code was written before γ = 2 was added, so it had three panels (Gaussian, Student t3, γ = 1) and missed the case where the coarse frequencies matter most. Its legend sat inside the last panel, its titles did not say that the one-minute detector has no guarantee under noise, and its axis label did not say that the medians are among detected paths only.

**HYPOTHESIS.** Four panels with the legend below them and explicit titles and labels show all laws without hiding data or overstating validity.

**CHANGES IMPLEMENTED.** `part_figures`: four panels (Gaussian, Student t3, γ = 1, γ = 2), the noise panels marked "1 min not valid", the axis labelled "median delay among detections", and one legend below the panels. The runtime note in the script's docstring was corrected to the measured times.

**EXPERIMENTS PERFORMED.** `python experiments/e17_multifrequency.py figures`.

**RESULTS.** `results/figures/e17_delays.png`. Under noise the plotted coarse detectors use plain blocks.

**IMPROVEMENTS.** The figure matches the tables.

**REMAINING ISSUES.** Median delays are among detected paths only; the report's tables give the detection shares next to them.

**NEXT ITERATION.** Possible follow-ups, not done here: a confidence-sequence baseline for each frequency (section 8 of the note); a data-driven choice of weights that keeps the proof (weights fixed at calibration time are allowed by Theorem 1); and a real-data test on a market or sampling scheme with strong one-minute noise, where the synthetic results say the coarse frequencies should matter.
