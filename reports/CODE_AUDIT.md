# Code audit: anytime-valid volatility monitor (avmonitor)

**Plain-language summary (for a beginner)**

1. We re-ran the whole test suite (581 tests, all pass) and then read the core maths line by line, looking for the kind of mistake that quietly breaks a statistical guarantee: using future data, wrong boundaries, bad inputs that are silently accepted.
2. The core e-detector maths is sound: the statistic never goes negative, its average under "nothing changed" equals the step count as the theory says, the alarm level is exactly the threshold, and nothing after a time step can change what the monitor did before it (checked by altering the future and comparing).
3. We found no wrong formula, but six places where bad input was silently accepted and turned the detector into a dead switch (for example a threshold of NaN never alarms). All six are fixed with a test written first.
4. Two benchmark detectors still go dead after a single missing value; that is reported, not changed, because changing it could move published benchmark numbers.
5. No number printed in any document changed: the full suite passes (637 tests, 56 new) and the quick reproduction tier is byte-identical to the stored results.

## Files read closely

`detectors.py`, `robust.py`, `monitor.py`, `confseq.py`, `guard.py`, `data.py` (core numerics only, as agreed). Checked for off-by-one errors, look-ahead, units, NaN and empty input, state shared between calls, silent fallbacks, wrong defaults.

Verified by test (SYNTHETIC data, fixed seeds): statistic nonnegative for SR and CUSUM, up and down, including the adaptive bet; SR path equals the hand recursion; CUSUM never exceeds SR; E[M_t] = t under the null with a closed-form baseline (within 1%); every bet factor has mean 1; false-alarm rate within m/A; alarm fires at statistic >= threshold, not >; monitor alarm level is exactly 2A per side; truncation never exceeds its cap; calibration window strictly precedes monitored steps; events up to a cut do not change when later returns are altered (plug-in and confidence-sequence baselines); adaptive bet is predictable; intraday scale uses earlier days only; replay with the same seed is bit-identical and streaming equals batch equals chunked; confidence sequence covers (miss rate below 5%) and the streaming and vector versions agree.
